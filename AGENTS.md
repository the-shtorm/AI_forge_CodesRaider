# Работа с репозиторием Softline Store

Умный поиск по каталогу ПО и оборудования. Команды в этом файле даны от корня репозитория, если рядом не указан другой каталог. Развёртывание и импорт подробно описаны в [README.md](README.md), устройство поиска и результаты проверок — в [docs/RESEARCH.md](docs/RESEARCH.md).

## Где вносить изменения

| Каталог | Назначение |
| --- | --- |
| `frontend/` | React, JavaScript и Vite. `CatalogPage.jsx` и `Filters.jsx` управляют выдачей, `catalogRoute.js` хранит формат URL, `AssistantChat.jsx` отвечает за ИИ-подбор, `events.js` отправляет события. |
| `backend/` | Spring Boot на Java 21. В пакете `ru.codesraider.smartsearch` код поиска лежит в `search`, импорт снимка — в `catalog`, журнал и аналитика — в `analytics`. Каталог и события хранятся в SQLite, поисковый индекс — в Lucene. |
| `model/` | FastAPI на Python 3.12 с uv. `app.py` и `encoder.py` обслуживают энкодер E5, `search_contract/` содержит схемы и примеры публичного API. Бизнес-обработчики публичного API находятся в Spring. |
| `contracts/` | Контракты публичного поиска и внутреннего энкодера в OpenAPI, схемы SQLite в `contracts/sql/`. |
| `backend/acceptance/` | Скрипты проверки работающего API, поисковые сценарии и эталонные данные. |

## Запуск

- Для проверки с небольшим встроенным каталогом запусти `docker compose -p softline-demo up -d --build --wait app`. Spring отдаёт витрину и API на `http://127.0.0.1:8080`. Готовность проверяй через `/actuator/health/readiness`, сведения об активном снимке — через `/health`.
- Для разработки интерфейса оставь Spring запущенным и выполни `npm ci` и `npm run dev` в `frontend/` с Node.js 24. Vite слушает порт `5173` и проксирует `/v1` и `/health` через `SPRING_BASE_URL`, по умолчанию на `http://localhost:8080`. После изменения собранной витрины пересобери `app`.
- Базовый лексический поиск запускается без модельных сервисов. Профиль Compose `ml` поднимает энкодер E5. Qwen подключается отдельно через `compose.llm.yaml` и `LLM_GGUF`.
- Для полного фида используй `import-catalog.sh` в Bash или команды из README для PowerShell. Передавай исходный фид в контейнер для чтения. Импорт и запуск должны использовать один Compose-проект, чтобы Spring открыл тот же том `snapshots`. После успешной активации нового снимка перезапусти `app`. Для остановки стенда используй `down` без удаления томов `snapshots` и `events`.
- При работе за Nginx используй Spring как upstream для витрины и API. Домен и TLS настраиваются на прокси. Vite нужен для разработки.

## Что сохранять при изменениях

- Поддерживай поиск на разных выгрузках. Используй данные активного каталога для контекстных рекомендаций. Редакционный список `backend/src/main/resources/search/curated-offers.txt` применяется, когда контекстный `upsell` пуст. Товары из этой подборки проходят проверку по снимку и фильтрам.
- Держи прямую выдачу, `alternatives` и `upsell` отдельно. `direct_count` считает прямые совпадения. Роль `complement` требует подтверждённой совместимости, роль `related` описывает похожий или редакционный товар. Блок «Возможно, вас заинтересует» остаётся видимым для поискового запроса и при нулевой прямой выдаче.
- Сохраняй строковые идентификаторы в JSON и суммы `_minor` в минорных единицах валюты. Для переходов используй тип и ID цели, а для событий — исходный `offer_id`, `search_id`, блок и позицию показа. Если меняется контракт, согласуй обработчик Spring, клиент, схемы и примеры OpenAPI.
- При изменениях каталога проверяй открытие ранее импортированных снимков и импорт нового фида. Сохраняй переключение `active` после успешной сборки снимка. При изменениях модельных сервисов проверяй работу поиска и без них.
- При изменениях витрины проверь навигацию мышью и клавиатурой. Переход по карточке должен работать со всей её площади, а кнопки корзины и пояснения должны выполнять свои действия отдельно. На мобильных экранах мгновенные фасеты должны сохранять открытое состояние фильтров, фокус и ещё не применённые поля. Учитывай `prefers-reduced-motion` при добавлении анимаций.
- Храни изменения в исходниках и существующих конфигурациях. Локальные фиды, данные приложения, кеши моделей, зависимости и собранные артефакты держи вне коммита.

## Проверки

Выбирай проверки по затронутому участку и указывай в результате, какие из них запускались.

| Что проверить | Команда |
| --- | --- |
| Java-тесты | Из `backend/` выполни `./mvnw test`, в PowerShell — `./mvnw.cmd test`. Для отдельного теста добавь `-Dtest=ИмяТеста`. |
| Фронтенд | Из `frontend/` выполни `node --test` и `npm run build`. При изменении UI проверь затронутый сценарий на ширине компьютера и телефона. |
| Python и контракты | Из `model/` выполни `uv run --locked --group docs --group test python -m unittest discover -s tests` и `uv run --locked --group docs python export_openapi.py --check`. После правки схем обнови YAML той же командой экспорта без `--check`. |
| Работающий демостенд | Из корня выполни `python backend/acceptance/storefront_smoke.py http://127.0.0.1:8080 --requests 240 --workers 12`. |

Для изменений ранжирования и рекомендаций проверь точный артикул, обычный запрос, фильтры и нулевую выдачу. Проверки на полном фиде и приёмка Java-обработчика описаны в разделе «Проверка, остановка и диагностика» README.
