# Умный поиск для Softline Store

Репозиторий команды трека «Умный поиск на сайте» хакатона «ИИкузница». Витрина React обращается к Spring Boot и показывает товары из локального снимка каталога. Опциональный энкодер работает в FastAPI. [Локальный запуск и проверка витрины](frontend/README.md)

## Поиск по каталогу Softline

Spring принимает `POST /v1/search` на порту 8080. Импортёр читает XML Softline, сохраняет предложения и характеристики в SQLite и строит Lucene-индекс. Флаг `--embeddings` добавляет векторы E5 из FastAPI. Для артикула Spring делает точный поиск. При поиске по тексту он может объединить BM25 и векторную выдачу. При недоступности энкодера приложение продолжает читать лексический индекс.

На Linux импорт с эмбеддингами и запуск витрины выполняет `bash import-catalog.sh data/Mindbox.yml.gz.xml`. Относительный путь отсчитывается от корня репозитория. Скрипт также принимает абсолютный путь.

Из корня репозитория выполните в PowerShell следующие команды. В первой строке укажите путь к своей выгрузке.

```powershell
$feed = (Resolve-Path "$env:USERPROFILE/Downloads/Mindbox.yml.gz.xml").Path
docker compose --profile ml up -d --build --wait model
docker compose build app
docker compose run --rm --no-deps --volume "${feed}:/catalog.xml:ro" app import --embeddings
docker compose up -d --force-recreate --wait app

$body = [Text.Encoding]::UTF8.GetBytes((@{ q = 'Как восстановить файлы после сбоя?' } | ConvertTo-Json))
$result = Invoke-RestMethod 'http://localhost:8080/v1/search' -Method Post -ContentType 'application/json' -Body $body
$result | Select-Object mode,index_version,direct_count
$result.top4 | Select-Object role,offer_id,sku,name,price_minor,currency
```

Для проверки по артикулу используйте `EP2-06605`. На снимке от 25 ноября 2026 года ожидается предложение `473582` с ценой 36 584 ₽. Поле `price_minor` содержит копейки. Доступность индекса и совместимого энкодера видна в [состоянии Spring](http://localhost:8080/health).

Для лексического запуска достаточно образа `app`. Выполните импорт без `--embeddings` и запустите Spring. Новый снимок активируется после успешного импорта, а запущенный Spring открывает его при перезапуске. Снимки сохраняются в томе `snapshots`, журнал — в отдельном томе `events`. Каждая успешная выдача получает `search_id`, в том числе пустая. [Контракт поиска](docs/SEARCH_API.md)

Иерархический поиск по всему каталогу требует снимка `catalog-v1.5` или новее. После обновления образа повторите импорт полного фида. Диагностика редакционной подборки доступна в `curated_offer_diagnostics` файла `manifest.json` и в выводе импортёра.

На снимке с векторами `SEMANTIC_MODE=auto` включает смысловой поиск по задаче, когда профиль FastAPI совпадает с профилем индекса. Для сравнения на том же снимке задайте `SEMANTIC_MODE=lexical` и пересоздайте контейнер `app`. Поле `mode` в ответе показывает, какой путь выполнился для данного запроса.

## Локальный компилятор запросов Qwen

Строка поиска и чат используют один обработчик Spring. Правила разбирают артикулы, лицензии и бюджет. Для неоднозначной задачи Qwen может выбрать назначение или две совместимые операции. Spring проверяет программу и выбирает SKU в активном снимке. Поле `program.compiler` показывает, какой разбор сработал. Кнопка «Почему этот товар?» открывает пояснение по фактам сохранённого показа.

После импорта каталога подключите локальную модель командами для Bash. Для проверки без полной выгрузки можно импортировать `backend/src/main/resources/search/demo.xml` той же командой импорта.

```sh
export LLM_GGUF="/tmp/softline-qwen.gguf"
curl -fL --retry 2 -o "$LLM_GGUF" https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/resolve/91cad51170dc346986eccefdc2dd33a9da36ead9/qwen2.5-1.5b-instruct-q4_k_m.gguf
echo "6a1a2eb6d15622bf3c96857206351ba97e1af16c30d7a74ee38970e434e9407e  $LLM_GGUF" | sha256sum -c -
docker compose -f compose.yaml -f compose.llm.yaml --profile ml up -d --build --wait app
```

Без GGUF обычный Compose запускает правила, Lucene и настроенный E5. Для перехода на новые словари и поля предложений повторите импорт: рецепт снимка обновлён до `catalog-v1.4`. Журнал событий совместим с прежней схемой. [Измерения качества и задержки](docs/SEARCH_EVALUATION.md)

## Первый смысловой поиск через FastAPI

Из корня репозитория запустите CPU-энкодер и передайте ему задачу покупателя.

```sh
docker compose --profile ml up --build -d --wait model
docker compose exec -T model python demo_search.py "Как вернуть документы после поломки диска?"
```

Команда отдельно проверяет энкодер на четырёх синтетических описаниях. Для этого примера первой должна идти карточка `backup`. Первая сборка сохраняет веса E5 в образе, последующие запуски используют их автономно. [HTTP-примеры, локальный запуск и тесты](docs/SEARCH_API.md#рабочий-сервис-fastapi)

[Спецификация реализации бэкенда](docs/BACKEND_SPEC.md) связывает пакеты Spring, HTTP-контракт React, поля SQLite и этапы приёмки.

```sh
docker compose --profile docs up -d --build api-docs
```

## Запуск через Docker

Из корня репозитория соберите приложение и импортируйте выгрузку. Укажите абсолютный путь к файлу на хосте. Для импорта и запуска нужен Docker Compose с поддержкой `depends_on.required` (v2.20+).

```sh
docker compose build app
docker compose run --rm --no-deps -v "/absolute/path/Mindbox.yml.gz.xml:/catalog.xml:ro" app import
docker compose --profile dev up --build -d
```

PowerShell принимает путь к файлу в форме `D:/path/Mindbox.yml.gz.xml:/catalog.xml:ro`. После импорта нового снимка выполните `docker compose restart app`, чтобы Spring открыл его. Снимки и журнал хранятся в именованных томах `snapshots` и `events`. Поле `search_ready` в `GET /health` показывает, открыт ли снимок и доступен ли журнал для записи. Docker проверяет эти же условия через `/actuator/health/readiness`.

| Сервис | Адрес | Назначение |
|---|---|---|
| `app` | [localhost:8080](http://localhost:8080) | Spring Boot на Java 21 отдаёт собранный React. Маршрут `/health` сообщает о доступности Spring и HTTP-сервиса FastAPI. |
| `frontend` | [localhost:5173](http://localhost:5173) | Сервер разработки Vite с React. Изменения в `frontend/src` подхватываются из рабочей копии. Запросы `/health` и `/v1` проксируются в `app:8080`. |
| `model` | `http://model:8000` в сети Compose | FastAPI на Python 3.12. Служебный маршрут `/health` отражает состояние HTTP-процесса. |

В профиле `dev` Compose ожидает готовности `model` перед запуском `app`, затем готовности `app` перед запуском `frontend`. Основной интерфейс и Spring API доступны на одном порту `8080`. Порты на хосте можно задать переменными `APP_PORT` и `FRONTEND_PORT`.

Для запуска только Spring со встроенной сборкой React используйте `docker compose up --build -d app`. Профиль `ml` добавляет внутренний FastAPI к этому варианту. Остановка полного стенда выполняется из того же каталога.

```sh
docker compose --profile dev down
```

### Витрина и профили

Откройте [витрину с каталогом Softline](http://localhost:8080/) после импорта снимка. Выберите «Закупщик оборудования», введите `сер`, затем сравните список с профилем «Администратор ПО». Подсказки ведут к сущностям того же снимка. Выберите строку клавишами ↓ и Enter или мышью. Свободный запрос `сервер` отдаёт приоритет готовым устройствам в обычном режиме и серверному ПО для администратора. Артикул `EP2-06605` открывает ту же лицензию Office при обоих профилях.

### Демо витрины

В каталоге `frontend` выполните `npm ci` и `npm run dev`. Откройте [демо витрины](http://127.0.0.1:5173/?demo=1) для проверки поиска, фильтров и сценария Pantum на встроенной выборке. В чате спросите «Офис без подписки», затем уточните ОС или бюджет. Демочат отвечает по заданным правилам. В обычном режиме витрина и чат отправляют запросы в Spring Boot.

Помощник открывается внизу экрана. В браузере остаются три последних диалога. Диалог удаляется через семь дней после последнего сообщения. История демо хранится отдельно от обычного режима.

## Что должно работать на стенде

- Поиск понимает опечатки, раскладку, жаргон и контекст категории, сегмента и сессии. По точному артикулу открывается предложение. По названию продукта, вендора или раздела первый переход ведёт на соответствующую страницу.
- Цель первой выдачи — четыре разных семейства. При двух прямых совпадениях оставшиеся места могут занять две программно проверенные допродажи. Если подходящих семейств меньше, API сообщает причину недобора. Для «сервер» ожидаются готовые машины, для «ПО для сервера» — программы.
- По `astra linux` первый переход ведёт к Astra Linux Special Edition. Рекомендация Кибер Бэкапа указывает версии и источник. Локальное исследование ссылается на запись о совместимости 17.1 с Astra Linux SE 1.8, план ветки — на отдельную запись для 17.2 с той же версией ОС. Версия SKU 418697 требует подтверждения перед заявлением о совместимости этой поставки. [Реестр для 17.1](https://astra.ru/ready-for-astra/compatible-software/versions/38258/) · [Реестр для 17.2](https://astra.ru/ready-for-astra/compatible-software/versions/41636/)
- Если точная модель отсутствует, первый ответ содержит проверенный аналог с указанием отличий, когда он есть в каталоге. Для выбора пилота заказчик выделяет качество допродаж. [Уточнения заказчика](supplementary/userQnA.md)
- Экран аналитики показывает долю запросов без прямых совпадений, уходы и конверсию на демонстрационных сессиях. Поиск, показы, клики, уточнения, корзины и заказы связываются по запросу и сессии. Источник событий виден в отчёте. Покупателю достаточно строки поиска с результатами и подсказками.

[Техническое задание](supplementary/Technical_details_smart_search.pdf) · [Ответы заказчика](supplementary/QnA_smart_search.md) · [План ветки](docs/HACKATHON_PLAN.md)

## Данные и результаты исследования

По отчётам, снимок `Mindbox.yml.gz.xml` от 25 ноября 2026 года содержит **136 040 предложений**, из них **44 601** доступны. В каталоге 4 413 семейств ПО и 8 125 позиций электроники без `group_id`. Доступность определяется флагом `available`. Цену, версию и условия лицензии нужно проверять у конкретного предложения. Путь к выгрузке предусмотрено передавать через `CATALOG_PATH`. Для аналитики стенда нужны помеченные синтетические события и коммерческие признаки, пока данные Метрики, заказов и маржи отсутствуют в checkout.

В Excel десять контрольных запросов с целевым первым URL. Восемь целей — продуктовые семейства. «мтс» ведёт на страницу МТС Линк, а «кибер бэкап» — на страницу Киберпротекта с фильтром категории 1033. Правильность первого перехода и состав товарных карточек проверяются по отдельности. [Контрольные запросы](supplementary/SearchQueries.xlsx)

| Опубликованный эксперимент | Наблюдение |
|---|---|
| SQLite FTS5/BM25 по названиям 44 601 доступного предложения, с группировкой в четвёрке | По 9 из 10 запросов есть хотя бы один результат. По 3 из 10 есть четыре разные группы. По «сервер» в первой четвёрке два программных продукта и две конфигурации одной модели DEPO. Локальное исследование `RESEARCH.md`. |
| SQLite FTS5/BM25 по названию и описанию 44 601 доступного предложения | Первый SKU относится к ожидаемому семейству в 4 из 8 запросов с целью-семейством. По «сервер» все четыре первых результата относятся к ПО. [План ветки](docs/HACKATHON_PLAN.md#2-что-уже-показал-эксперимент) |
| Фильтр по двум категориям готовых серверов | Исследование нашло 22 доступных предложения с 17 разными названиями. Этого достаточно, чтобы собрать демонстрационную четвёрку без повторов. Локальное исследование `RESEARCH.md`. |

Это результаты разных локальных прогонов. Их метрики имеют разные знаменатели и точки отсчёта. Показатели нового ранжирования, задержки стенда и бизнес-эффекта ещё предстоит измерить.

## Архитектура и порядок реализации

Для общего плана используем архитектуру ветки `research`. Java 21/Spring Boot импортирует XML, использует Lucene для поиска и хранит каталог и события в отдельных базах SQLite. React показывает выдачу и аналитику. Docker Compose запускает приложение. Опциональный сервис FastAPI с `multilingual-e5-small` позволяет сравнить лексический и гибридный поиск на одних и тех же размеченных запросах. Локальная Qwen опционально компилирует поисковые запросы и выбирает факты для пояснения карточек. Python, SQLite FTS5 и Streamlit из локального плана задают вариант быстрого прототипа. Эксперименты с SQLite FTS5 служат точкой отсчёта. [Техническая архитектура](docs/TECHNICAL_ARCHITECTURE.md) · Локальный план `PLAN.md`.

1. Получить XML, импортировать весь снимок, восстановить иерархию, сопоставить десять эталонных URL с сущностями. Сохранить исходный прогон SQLite по названию и описанию для сравнения с Lucene.
2. Провести сквозной сценарий `EP2-06605` → предложение 473582 → клик в аналитике. Полное название Office должно вести на страницу семейства. Для той же цепочки подготовить карточку, причины совпадения и журнал событий.
3. Добавить нормализацию, распознавание назначения и подбор доступных предложений. В первую очередь проверить различие между названием и упоминанием платформы (`astra linux`) и слитное написание известных семейств (`max patrol`). Применять все обязательные характеристики к одному SKU и сворачивать одинаковые модели при показе.
4. Проверить восемь продуктовых семейств среди прямых карточек топ‑4 и отдельно две навигационные цели из Excel. Дополнительно разметить 80 запросов, из них 40 оставить для настройки и 40 для закрытого теста. Для включения E5 сравнить режимы на одном наборе. Цель команды — прирост nDCG@4 минимум на 0,05 для запросов по задаче, сохранение FamilyHit@4, точных SKU и навигации при p95 до 500 мс.
5. Проверить, что стенд запускается с подготовленным каталогом при выключенной модели, а история переживает перезапуск. К сдаче подготовить публичный URL демо, описание и инструкцию восстановления, перечень зависимостей и лицензий, измерения качества и заполненный шаблон стоимости запроса со скачиванием без авторизации.
