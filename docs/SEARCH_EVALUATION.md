## Условия проверки

Проверка шла через публичный `POST /v1/search`. В двух выборках по 30 свободных запросов на 15 задач. Первую использовали при разработке. Дополнительные формулировки и 45 других семейств зафиксировали до реализации. Для новых семейств поровну использованы удаление буквы, замена буквы и перестановка соседних букв. Версии чередовались на одном CPU-стенде. Основные задачи и официальный Excel отправлялись трижды в каждом из трёх режимов (старый сервис, новый сервис, новый с выключенной Qwen), остальные запросы — один раз в старый и новый сервисы. Всего в сравнении 1 084 поисковых ответа, HTTP-ошибок не было. Топ‑4 основных задач совпал во всех повторах каждого режима.

Релевантность карточки определяется типом товара по категории и явным названиям в исходном XML. В nDCG@4 позиция учитывается с логарифмической скидкой, идеальная выдача ограничена числом доступных с ценой релевантных групп, максимум четырьмя. Для архиваторов доступна одна такая группа. На отложенных задачах подходящих прямых карточек было 37 из 44 до изменений и 86 из 88 после. Все десять прежних попаданий сохранились, появилось 14 новых. Проверка охватывает знакомые классы задач с другими формулировками. Для оценки пригодности конкретной лицензии и конверсии нужны отдельная экспертная разметка и трафик.

## Что изменилось

- Поиск использует активные категории каталога, а для широкого раздела «Связь» проверяет принадлежность предложения к ПО МТС Линк. Пустая одноимённая категория уступает товарному семейству. Результаты внутри подтверждённого назначения ранжируются по BM25. На проверенном снимке появились карточки по «вебинар», «удаленный доступ», «резервное копирование» и «Pixso Enterprise».
- Простые назначения и сочетания двух однозначных задач компилируются правилами. Qwen получает ограниченный словарь операций для неоднозначных формулировок, а каталог проверяет составленные условия. Все 30 запросов разработки дали тот же результат с отключённой Qwen. На отложенных задачах модель выбрала операцию для одного из 30 запросов. Для слабых текстовых совпадений E5 ранжирует кандидатов с лексическим подтверждением. При пустом результате запасной путь проверяет покрытие слов в заголовках. Обязательные свойства, исключения и доступность применяются к конкретному SKU.
- Справочник реальных товарных названий разрешает одну буквенную ошибку при однозначном совпадении семейства. Цифры и разделители в таких названиях сохраняются. Товар без семейства при точном поиске получает самостоятельную карточку. В случаях вроде `3275` подсказки позволяют выбрать артикул или ID. Для прямого перехода также доступны `sku:3275` и `id:3275`. На 64 SKU остался один намеренно неоднозначный номер без автоматического перехода.

## Границы результата

Остались шесть пустых отложенных запросов, включая «Склеить видеофрагменты», «Преобразовать изображение с буквами в текст» и «Автономное питание ПК при перебоях». По этим результатам правила не подгонялись. Строгая проверка версии и количества может оставить пустой выдачу, если необходимые факты SKU отсутствуют. Поэтому ещё один тест про лицензию Kaspersky на 10 ПК исключён из подсчёта проверяемых ограничений. Указание числа пользователей не подтверждает число устройств. Значения задержки получены при последовательных запросах на одном стенде.

## Проверки интеграции

Прошли 23 Java-теста и 32 HTTP-проверки в четырёх сценариях приёмки. На малом демонстрационном каталоге сохранились 57/57 попаданий и 13/13 правильных пустых ответов. Для прямой карточки и совместимого дополнения проверен API пояснений, для непоказанного товара — HTTP 404. Восемь параллельных клиентов отправили 64 поиска и повторили доставку 48 пар событий клика и заказа по товару без семейства. Метрики вернули 16/64 пустых поисков и 48/64 конверсий. Отчёт за зафиксированный период и сохранённое пояснение читались после перезапуска.

## Как повторить

Запустить каждую версию сервиса на одном снимке полного XML. Тест по 60 описаниям читает эталоны из исходной выгрузки, проверяет совпадение её хеша с работающим индексом и сохраняет результаты каждого запроса.

```bash
python3 backend/acceptance/catalog_tasks.py /path/to/Softline.xml --url http://localhost:8080 --repeat 3 --csv tasks.csv
```

## Как работает поиск

1. Spring открывает опубликованный снимок SQLite и Lucene. Ввод артикула, ID или выбор подсказки даёт поиск в этом каталоге. Правила выделяют бюджет, версию, отрицания, платформу, количество и срок. В запросе задачи слова покупателя ограничивают допустимые назначения.
2. Для неоднозначной задачи модель выбирает одну разрешённую операцию или две с пересечением либо объединением. Исполнитель применяет фиксированные SQL-предикаты к одному SKU перед группировкой, отбором по цене и вычислением фасетов. При текстовом поиске доступны Lucene и индекс E5. Режим поиска и фактический компилятор возвращаются раздельно. Этот способ разделить генерацию и исполнение заимствован из XERJ. [XERJ Query-1](https://xerj.org/blog/xerj-query-ai-model) · [Компилятор](../backend/src/main/java/ru/codesraider/smartsearch/search/QueryPlan.java) · [Исполнитель](../backend/src/main/java/ru/codesraider/smartsearch/search/SearchCatalog.java)
3. Один вызов поиска атомарно сохраняет показ и диагностику в обычном журнале Spring. По кнопке пояснения модель выбирает один из фактов сохранённой карточки. При отключённой модели готовую фразу формирует сервер. Для исторических показов без сохранённых фактов API возвращает 404. [Журнал](../backend/src/main/java/ru/codesraider/smartsearch/analytics/EventStore.java) · [Контракт](SEARCH_API.md)

## Регрессии и продуктовая аналитика

- Прошли 20 тестов Java и 32 HTTP-проверки, по восемь для обычного снимка, удалённого кода картриджа и двух очередей резерва. Проверены принадлежность к подборке, фильтры в одной лицензии, фасеты, профили, исключения, точные коды, дополнения и функциональные аналоги. Все 13 Python-тестов прошли с реальными весами E5. YAML OpenAPI совпал с экспортом.
- В Chromium проверены выдача, пояснение с `source=llm`, показ, клик, повторный поиск и атрибуция заказа на точный SKU. Для чата проверены восстановление истории, позиция карточки и повторное открытие без удвоения показов.
- В изолированном тесте с четырьмя поисками и тремя сессиями после повторного открытия SQLite пустые ответы составили 2/4, уходы после пустой выдачи — 1/2 завершённых сессий с неудачей, конверсии — 1/3. Повтор пакета событий и чтение пояснения сохранили эти значения. Проверены также группы причин, границы версии индекса и источника. [Регрессия аналитики](../backend/src/test/java/ru/codesraider/smartsearch/analytics/SearchMetricsTest.java)
- В контейнере восемь параллельных клиентов выполнили 64 поиска. Для 48 успешных сессий пакет с кликом и заказом отправлялся дважды. Записались 64 уникальных поиска, метрики показали 16/64 пустых поисков и 48/64 конверсий. После перезапуска контейнера отчёт за зафиксированный период совпал полностью, пояснение осталось доступным. Для сборки за прокси доверенный CA передан временным BuildKit-секретом.

## Воспроизведение

Из корня проекта импортируйте `backend/src/main/resources/search/demo.xml` с флагом `--embeddings` и запустите два экземпляра Spring на разных портах с одним снимком, разными `SEARCH_EVENTS_DB` и одинаковым `MODEL_BASE_URL`. Для порта 8082 дополнительно задайте `SEARCH_LLM_URL` и `SEARCH_LLM_TIMEOUT_MS=5000`. Путь к модели и контрольная сумма приведены в README. Для сравнения с базами запустите master на порту 8083 со своим импортом этого же XML и E5, а исходную ветку на 8084 с `CATALOG_PATH`, отдельным `EVENTS_PATH` и тем же Qwen. [Запуск Spring и моделей](../README.md)

```sh
python backend/acceptance/benchmark.py --rules http://localhost:8081 --model http://localhost:8082 --reference http://localhost:8083 --previous http://localhost:8084 --repeat 3 --csv /tmp/search.csv
python backend/acceptance/build_fixtures.py backend/src/main/resources/search/demo.xml /tmp/search-fixtures
cd backend
./mvnw test
```

Для каждого из четырёх сгенерированных XML импортируйте отдельный снимок, запустите Spring на этом снимке и выполните `./mvnw -Psearch-acceptance -Dsearch.baseUrl=http://localhost:8080 -Dsearch.scenario=baseline verify` с соответствующим названием сценария. [Процедура приёмки](SEARCH_API.md#приёмка-поискового-обработчика-spring)
