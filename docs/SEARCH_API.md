# HTTP API умного поиска Softline

Витрина вызывает публичный API Spring Boot. FastAPI публикует интерактивный контракт для разработчиков и описывает внутренний энкодер, к которому обращается Spring. Схемы OpenAPI 3.1 подходят для импорта в Postman и генерации клиента. [Публичная спецификация](../contracts/search.openapi.yaml) · [Спецификация энкодера](../contracts/model.openapi.yaml)

## Открыть документацию

Из корня репозитория запустите справочный стенд. Он работает независимо от Java, React, каталога и весов модели.

```sh
docker compose --profile docs up -d --build api-docs
```

| Документ | Swagger UI | ReDoc | JSON |
|---|---|---|---|
| Поиск и аналитика | [Открыть](http://127.0.0.1:8001/docs) | [Читать](http://127.0.0.1:8001/redoc) | [Скачать](http://127.0.0.1:8001/openapi.json) |
| Внутренний энкодер | [Открыть](http://127.0.0.1:8001/model/docs) | [Читать](http://127.0.0.1:8001/model/redoc) | [Скачать](http://127.0.0.1:8001/model/openapi.json) |

Порт справочного стенда на хосте задаёт `API_DOCS_PORT`, по умолчанию `8001`. Для запуска через uv выполните команду из каталога `model` с Python 3.12.

```sh
uv run --locked uvicorn search_contract.api:app --host 127.0.0.1 --port 8001
```

В Swagger выберите операцию и один из именованных примеров. **Try it out** проверяет обязательные поля, типы и пределы значений. У публичных операций правильный запрос на справочном стенде возвращает `501 CONTRACT_ONLY`. Образец целевого успешного ответа находится в **Responses → 200 → Examples**. Команды ниже используют адрес будущего рабочего обработчика `http://localhost:8080`. Для проверки формы запроса замените порт на `8001`.

Стандартные веб-интерфейсы FastAPI загружают ресурсы Swagger UI и ReDoc с CDN. Для автономной работы доступны оба YAML-файла в репозитории.

## Маршруты

| Метод и путь | Вызывает | Результат целевой реализации |
|---|---|---|
| `GET /v1/suggest` | Строка поиска | До шести вариантов с ID для выбора. |
| `POST /v1/search` | Витрина | Переход к сущности, товарные карточки, причины подбора и ID поиска. |
| `GET /v1/entities/{kind}/{id}` | Карточка или навигация | Варианты SKU и дочерние переходы с учётом фильтров. |
| `POST /v1/events` | Витрина и демонстрационный адаптер заказов | Атомарная запись пакета событий, `204` с пустым телом. |
| `GET /v1/analytics` | Отчёт магазина | Метрики и причины неудач за период. |
| `GET /health` | Витрина, мониторинг | Spring уже возвращает `status` и `model_service`. Показатели готовности индекса и семантики появятся с ними. |
| `GET /health`, `GET /ready`, `POST /internal/v1/embeddings` | Spring и импортёр → FastAPI | Доступность процесса, готовность модели и векторы. В сети Compose база — `http://model:8000`. |

Идентификаторы в JSON передаются **строками**. `offer_id` — ID конкретного предложения XML. `sku` — артикул `vendorCode`, который может повторяться или отсутствовать. `family_key` группирует лицензии или конфигурации модели. `search_id` выдаёт сервер на каждый отправленный поиск, `session_id` задаёт клиент для своей анонимной сессии, а `event_id` сохраняется при повторной доставке события.

Тела запросов и успешных ответов используют `application/json`. Запросы к локальному справочному стенду доступны без ключа. В приложении React обращается к Spring на том же origin, а к энкодеру по внутренней сети обращается Spring.

## Сквозной пример для витрины

1. При вводе `EP2-0` запросить `GET /v1/suggest?q=EP2-0`. Ожидаемый вариант для Office содержит `kind="offer"` и `target_id="473582"`. Без подходящих подсказок приходит `200 []`.
2. По клику или Enter отправить исходный префикс вместе с выбранным типом и ID. При обычном вводе отправить полный текст в `q`. Отправка создаёт одну запись поиска на сервере.

```sh
curl -X POST http://localhost:8080/v1/search -H "Content-Type: application/json" \
  -d '{"q":"EP2-0","selected_target":{"kind":"offer","target_id":"473582"},"session_id":"demo-session-1"}'
```

В PowerShell тело того же запроса можно собрать из хеш-таблицы.

```powershell
$body = @{
    q = 'EP2-0'
    selected_target = @{ kind = 'offer'; target_id = '473582' }
    session_id = 'demo-session-1'
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://localhost:8080/v1/search' -ContentType 'application/json' -Body $body
```

3. Сохранить `search_id` и показать карточки в полученном порядке. Для точного `EP2-06605` ориентир снимка — `primary_target.kind="offer"`, `offer_id="473582"`, `family_key="family/391338"`, `price_minor=3658400`, `currency="RUB"`. Это 36 584 ₽. По запросу названия семейства витрина может открыть `GET /v1/entities/family/391338` и показать варианты.
4. При клике отправить событие на `POST /v1/events` с возвращённым `search_id`, фактическим `offer_id`, ролью, блоком и позицией с единицы. Покупка из адаптера содержит собственный `event_id` и купленный `offer_id`. Полный пример пакета «клик + заказ» приведён в Swagger.

## Правила обработчика поиска

- Сначала разрешить выбранную подсказку или точный артикул. Неизвестная пара `kind/target_id` даёт `400 UNKNOWN_TARGET`. Явные фильтры действуют и при переходе по подсказке.
- `context.category_id`, сегмент, демонстрационный профиль и история сессии помогают при неоднозначности. `filters.category_id` — обязательное ограничение. Платформа, версия, тип лицензии, срок и количество устройств или мест должны одновременно подтверждаться у одного предложения. При открытии карточки повторить фильтры отдельными параметрами URL, например `/v1/entities/family/22268?version=5.0&device_count=5`.
- `limit` по умолчанию равен 4, диапазон 4–50. В `top4` может быть от 0 до 4 уникальных семейств. При расширенном просмотре дополнительные прямые семейства идут в `more_results`. Сумма двух массивов ограничена `limit`. `direct_count` считается до ограничения размера выдачи.
- Сначала идут прямые результаты, затем совместимые дополнения. У каждого дополнения `anchor_offer_id` указывает на показанную прямую карточку, а у всех обязательных `checks` результат `pass` и источник. Несовместимость или неизвестное значение исключают пару. Навигация живёт в `primary_target`, функциональные замены с описанием отличий — в `alternatives`.
- Полная четвёрка получает `shortfall_reason=null`. При нехватке проверенных семейств вернуть `NOT_ENOUGH_VERIFIED_FAMILIES`. Для неизвестного запроса вернуть `200`, `direct_count=0`, пустой `top4` и `NO_DIRECT_MATCH`. Карточка существующего семейства с пустым `offers` после фильтрации также получает `200`. Неизвестная сущность получает `404 ENTITY_NOT_FOUND`.
- Доступное предложение с ценой получает `offer_tier="primary"`. Резерв рассматривается, когда у кандидатов подходящей роли и с нужными свойствами закончилась первая очередь. В резерве сначала показываются предложения с известной ценой. Флаги `available` и `price_minor` независимы. Нулевая или неизвестная цена в XML возвращается как `null`. Бюджет проверяется для всей конфигурации при известной единице цены.
- Недоступный индекс даёт `503 CATALOG_UNAVAILABLE`. При доступном индексе и отказе FastAPI продолжить лексический поиск и вернуть `200` с `mode="lexical"`. Фактически применённые условия сохраняются в `applied_filters`.

### Кибер Бэкап от подсказки до подборки

1. На `GET /v1/suggest?q=кибер%20бэ` выбрать подсказку `{"kind":"collection","target_id":"cyberprotect-1033","label":"Кибер Бэкап"}`.
2. Отправить `POST /v1/search` с телом `{"q":"кибер бэ","selected_target":{"kind":"collection","target_id":"cyberprotect-1033"}}`. Свободный ввод `{"q":"кибер бэкап"}` выбирает ту же подборку. В ответе `applied_filters` включает `vendor_id="cyberprotect"` и `category_id="1033"`, а `primary_target` содержит тип `collection`, ID `cyberprotect-1033` и [точный адрес из Excel](https://store.softline.ru/cyberprotect/?filter%5Bcategory%5D%5B%5D=1033).
3. В снимке 560 доступных SKU этой области образуют ровно четыре прямых семейства — 173614, 173615, 442025 и 444870. Ожидаются `direct_count=4` и `shortfall_reason=null`. Выбор подходящего SKU внутри семьи и взаимный порядок семейств могут меняться. Пример полного ответа опубликован в Swagger под именем `backup`.
4. Открыть `GET /v1/entities/collection/cyberprotect-1033`. Сервер восстанавливает обе границы из ID, даже если клиент не передал фильтры. Дочерние переходы ведут только внутрь подборки. Дополнительный фильтр сужает её. При противоречащем `?category_id=687` вернуть известную сущность с пустыми `offers` и `children`. Применяется то же пересечение при поиске: конфликт даёт `200`, пустой `top4`, `direct_count=0` и `NO_DIRECT_MATCH`. При конфликте в `applied_filters` сохраняется явно запрошенное значение поля, здесь `category_id="687"`, и унаследованный `vendor_id`. Ограничение самой подборки сохраняется в `primary_target`. Сервер проверяет оба условия.
5. Для клика по заголовку передать событие `block="navigation", target_kind="collection", target_id="cyberprotect-1033"`. У клика по карточке передаётся фактический `offer_id`. Контроль утечки фильтров — SKU 477550 («Кибер Файлы», другая категория) и 53955 (Uranium Backup, другой вендор).

## События и отчёт

Публичный пакет — непустой JSON-массив. Витрина отправляет `impression`, `click`, `reformulation`, `add_to_cart`, а адаптер заказов — `order`. Событие `search` пишет сам обработчик поиска. У перехода к вендору передаются `target_kind` и `target_id`. При выборе варианта в деталях отправляется `block="details"` и его фактический `offer_id`. Повтор с тем же `event_id` сохраняет первую запись. Некорректная строка отклоняет пакет целиком.

Заказ разбивается по товарным позициям. Сервер ищет последний предшествующий клик с теми же `session_id` и `offer_id`. При отсутствии такого клика заказ сохраняется с `search_id=null`. Клик по соседней лицензии того же семейства не создаёт атрибуцию.

```sh
curl -G http://localhost:8080/v1/analytics \
  --data-urlencode 'from=2026-11-26T00:00:00+03:00' \
  --data-urlencode 'to=2026-11-27T00:00:00+03:00' --data-urlencode 'source=seed'
```

Границы периода задаются с часовым поясом, начало включено, конец исключён. Для пустого знаменателя `value=null`. В ответе сохраняются исходные числитель и знаменатель.

| Метрика | Числитель | Знаменатель |
|---|---|---|
| `zero_result_rate` | Запросы с `direct_count=0` | Все отправленные поиски |
| `abandonment_rate` | Завершённые неуспешные сессии без последующего клика или заказа | Завершённые неуспешные поисковые сессии |
| `conversion_rate` | Поисковые сессии хотя бы с одной атрибутированной позицией заказа | Все поисковые сессии |

Для демо сессия завершается после 30 минут бездействия. `source=seed` выбирает синтетические события, `source=demo` — действия на стенде. `failures` содержит причины с примерами запросов и рекомендуемым действием менеджера. Причина `catalog_gap` остаётся гипотезой до проверки полного каталога.

## Внутренний контракт энкодера

Spring берёт `profile_id` из `GET /ready` при создании индекса и сохраняет его в манифесте. Перед онлайн-запросом используется профиль активного снимка. В `POST /internal/v1/embeddings` для `query` передаётся ровно один непустой текст, для `passage` — от 1 до 32. Энкодер добавляет префикс один раз. Ответ сохраняет порядок текстов и содержит по одному L2-нормализованному вектору размерности 384 на текст. Профиль в примере Swagger и единичный вектор синтетические.

| HTTP | Условие | Действие клиента |
|---|---|---|
| `200` | Модель прогрета или эмбеддинги получены | Сверить профиль, размерность, число векторов и конечность значений. |
| `409 PROFILE_MISMATCH` | Профиль запроса и активной модели различается | Для онлайн-поиска выбрать лексический режим, для импорта сверить манифест. |
| `422 INVALID_REQUEST` | Пустой текст, неверный тип или размер пачки | Исправить входной пакет. |
| `503` | Модель не готова, перегружена или вернула непригодные векторы | Онлайн-поиск продолжает работу по лексическому индексу. |

У служебного `GET /health` в FastAPI ответ `{"status":"up"}` означает доступность процесса. `GET /ready` отражает готовность энкодера к вычислению. В каркасе его текущее состояние — `503 MODEL_NOT_READY`. [Спецификация сервиса эмбеддингов](FASTAPI_RETRIEVAL_HANDOFF.md)

## Приёмка поискового обработчика Spring

[SearchHandlerIT](../backend/src/test/java/ru/codesraider/smartsearch/SearchHandlerIT.java) вызывает публичные HTTP-маршруты работающего Java-приложения. Тест получает подсказку, передаёт её фактические `kind` и `target_id` в поиск, повторяет поиск по полному тексту и открывает сущность отдельным запросом. Для карточек сравниваются множества семейств, роли, привязка к SKU устройства, цена и наличие. Порядок между равноправными семействами свободный.

1. Из корня проекта подготовьте четыре тестовых XML. [Генератор](../backend/acceptance/build_fixtures.py) извлекает 13 реальных предложений и их дерево категорий. В копиях он меняет только отмеченные ниже свойства SKU и дату снимка.

```sh
python backend/acceptance/build_fixtures.py ../Mindbox.yml.gz.xml backend/target/search-fixtures
```

2. Для каждого файла импортируйте и активируйте его **в отдельном тестовом каталоге данных**. Выберите такой же `search.scenario`, как имя файла без расширения. Укажите адрес Spring со свежим индексом. В текущей сборке реализован только `/health`. Импорт и обработчики `/v1` входят в план реализации. Профиль приёмки запускается явно и считает HTTP 404 или 501 ошибкой.

3. Из каталога `backend` запустите проверку. Для Windows используйте `.\mvnw.cmd` вместо `./mvnw`. Параметр `search.baseUrl` по умолчанию равен `http://localhost:8080`.

```sh
./mvnw -Psearch-acceptance "-Dsearch.scenario=baseline" "-Dsearch.baseUrl=http://localhost:8080" verify
```

| Снимок | Что изменено в фикстуре | Ожидаемая выдача «Кибер Бэкап» |
|---|---|---|
| `baseline` | В группе 173614 дополнительно есть недоступный 421468 с ценой и недоступный 421471 с нулевой ценой | Четыре прямых семейства. Представитель 173614 — доступный 418697. Оба резервных варианта пропускаются. |
| `missing-code` | У PC-211P удалён `vendorCode`. У 536456 выключено наличие, у 539763 выключено наличие и обнулена цена | Два прямых семейства 173614 и 173615. Резерв из двух других семейств не заполняет свободные позиции. |
| `priced-reserve` | У всех шести предложений подборки выключено наличие. Только у 421468 сохранена цена | Одна прямая карточка 421468, `offer_tier=reserve`, `available=false`, `price_minor=10323600`. |
| `unpriced-reserve` | У всех шести выключено наличие и обнулена цена | Четыре разных семейства с `offer_tier=reserve`, `available=false` и `price_minor=null`. |

Во всех четырёх вариантах проверяются код ошибки исчезнувшей подсказки, ссылка из Excel и границы подборки. Запрос с `category_id=687`, чужим вендором или неподтверждённой версией `17.2` даёт пустой результат поиска и пустую карточку подборки. В резервных снимках то же верно для `available_only=true`.

Для Pantum в обычной фикстуре запрос двух устройств даёт две модели и два подтверждённых картриджа. В `missing-code` остаётся только картридж TL-C2318H у BM1800W, а у выдачи из трёх позиций появляется `NOT_ENOUGH_VERIFIED_FAMILIES`. Отдельный запрос P2500W исключает TL-C2318H во всех сценариях. При удалённом коде PC-211P остаётся один принтер. Если любой из двух SKU P2500W занял позицию прямого устройства, ссылка расходника должна указывать именно на показанный SKU.

Проверка аналога использует запрос «Нужен монохромный лазерный принтер A4 Pantum P2507». В тестовом снимке есть принтеры с нужным назначением, а P2507 встречается в описании расходника. Уже в первом ответе ожидаются `direct_count=0`, пустой `top4`, причина `NO_DIRECT_MATCH` и непустой `alternatives[]` с другой моделью устройства и описанием различий. Этот пример в Swagger называется `analog`.

## Обновление контракта

Схемы, маршруты и примеры публичного API хранятся в `model/search_contract/`, внутреннего — в `model/app.py`. Обновите их и экспортируйте оба файла OpenAPI из каталога `model`. Первая команда записывает YAML, вторая сверяет его с FastAPI, третья проверяет опубликованные примеры.

```sh
uv run --locked --group docs python export_openapi.py
uv run --locked --group docs python export_openapi.py --check
uv run --locked --group docs python -m unittest discover -s tests
```
