# Описание продукта — «Умный поиск для Softline Store»

**Команда CodesRaider · хакатон «ИИкузница» · трек «Умный поиск на сайте»**

Прототип помогает покупателям находить ПО и оборудование по артикулу, названию или описанию задачи. Поиск определяет, куда лучше направить покупателя, и ведёт к конкретной поставке, семейству с вариантами, вендору или подборке. Покупатель может сравнить предложения и проверить, почему товар оказался в выдаче. Команда магазина получает аналитику, по которой можно разбирать запросы без прямых совпадений и видеть, какие карточки открывают пользователи.

## Функциональность, реализованная за спринт

| Возможность | Что получает пользователь |
| --- | --- |
| Поиск по смыслу, названию и артикулу | Поиск понимает распространённые опечатки и переформулировки, различает оборудование и ПО для него. Точный артикул `EP2-06605` открывает конкретное предложение Microsoft Office, а запрос `astra linux` ведёт к семейству с вариантами. |
| Подсказки и фильтры | Подсказки появляются с третьего символа. Результаты можно уточнить по производителю, категории, цене, наличию, платформе и параметрам лицензии. Карточка открывается целиком, а мобильная панель фильтров сохраняет введённые значения при обновлении выдачи. |
| Аналоги и рекомендации | Поиск показывает подходящие замены, подтверждённые дополнения и похожие товары в отдельных блоках. Например, Pantum P2500W можно дополнить совместимым картриджем PC-211P. Когда контекстных рекомендаций нет, блок «Возможно, вас заинтересует» использует редакционную подборку из активного каталога. |
| «Подбор с ИИ» | Помощник принимает описание задачи, сохраняет контекст диалога, уточняет отдельные параметры и предлагает карточки из того же каталога. Для неоднозначных запросов доступен локальный разбор с Qwen. |
| Пояснения и сравнение цен | У карточек есть пояснение «Почему в выдаче». Для отдельных артикулов Pantum и «Киберпротекта» можно сравнить цену в каталоге с опубликованной ценой или РРЦ вендора. |
| Аналитика и демонстрационная корзина | Журнал связывает запросы, показы, клики, переформулировки и добавления в корзину. Отчёт группирует причины неудачного поиска и показывает долю запросов без прямых совпадений. Корзина и пробная покупка позволяют пройти демонстрационный сценарий целиком. |

## Функциональность, которую не успели реализовать

**Полноценный чат с ИИ-агентом через внешний API LLM.** Планировали, что покупатель сможет начать с общего описания, например «Нужно подготовить небольшой офис к открытию». Агент сам выяснил бы, какие задачи нужно закрыть, сколько будет рабочих мест и какой бюджет доступен. Затем он собрал бы подборку из нескольких категорий и предложил варианты комплектации с проверкой цены, наличия и совместимости по каталогу. В спринте выпустили поискового помощника с ограниченным диалогом и локальной Qwen. Интеграцию с внешним API и многошаговый подбор по широкой задаче завершить не успели.

## Подход и архитектура решения

1. **Каталог публикуется проверенными снимками.** Импортёр читает XML/YML, группирует поставки в семейства и сохраняет конкретные артикулы и параметры. SQLite хранит карточки и атрибуты, Lucene — текстовый индекс и, при гибридном импорте, векторы E5. Новый снимок активируется после проверок. Это позволяет повторять поиск на той же версии данных и отдельно хранить историю событий.
2. **Поиск выбирает способ обработки по запросу.** Артикулы и явные навигационные цели обрабатываются по каталожным полям и словарям. Для свободных формулировок Lucene объединяет лексические кандидаты с векторными совпадениями E5, если модель доступна. Qwen подключается выборочно, например когда запрос о задаче даёт пустую или неподходящую прямую выдачу. При недоступности моделей продолжает работать лексический поиск.
3. **Модель помогает понять задачу, коммерческие факты проверяет сервер.** Spring сверяет план поиска с допустимыми параметрами и проверяет ограничения на уровне конкретного SKU. Цены, наличие и ссылки берутся из каталога или проверенного источника. Группировка по семействам освобождает первые позиции для разных моделей. Для допродажи система учитывает совместимость и контекст запроса, а показы похожих и редакционных товаров учитываются отдельно от прямых совпадений.
4. **Витрина и API используют одну реализацию поиска.** Spring отдаёт React-интерфейс и публичное API с одного адреса. Идентификатор поиска связывает ответ с пояснениями и действиями покупателя. FastAPI и llama.cpp запускаются отдельными сервисами по необходимости. [Архитектура и API](RESEARCH.md#архитектура)

## Эффективность поиска

Полный снимок Softline содержал **136 040 предложений**, из них **44 601 доступное**. В снимке `catalog-v1.5` после группировки получилось **12 229 карточек**. Ниже приведены сравнительные замеры спринта на размеченных наборах. Hit@1 показывает, как часто нужный товар или тип товара оказывается первым. nDCG@4 оценивает релевантность и порядок первых четырёх результатов. [Описание каталога и методики](RESEARCH.md)

## Запуск и состав поставки

Для запуска демостенда из корня репозитория нужен Docker с Compose v2.20+ и BuildKit.

```sh
docker compose -p softline-demo up -d --build --wait app
```

Витрина и API доступны на `http://127.0.0.1:8080`. На пустом томе автоматически импортируется встроенный демокаталог. Для работы с полным каталогом требуется предоставляемая отдельно выгрузка Softline `Mindbox.yml.gz.xml`. Гибридный поиск включается при импорте с эмбеддингами E5. Локальный разбор с Qwen запускается через `compose.llm.yaml` с указанием файла весов. [Инструкция запуска, импорта и проверки](../README.md)

В поставку входят исходники React-витрины, Spring API и сервиса энкодера, конфигурации контейнеров, импортёр и демокаталог, контракты API и схемы хранения, тесты, сценарии оценки и результаты замеров.
